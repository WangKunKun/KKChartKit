## 3. 推荐下一编码任务：N1 值轴阈值分区进入通用模型

**默认建议先执行 N1，而不是直接整体扩张 G6。** 理由：缺口已被覆盖矩阵确认，现有原生绘制、OC 配置和测试可复用；不依赖未知业务规则，也不必重建坐标/交互底座。此为本轮排期建议，不表示该功能已实现或其他任务已获执行授权。

### N1 的明确范围

第一切片仅做**逐系列、按值轴阈值分区的颜色规则**，覆盖 Line / Area / Column / Bar / Combined 的适用组合：

- 样式使用 Foundation 的 RGBA 值；不向中立模型引入 UIColor、引擎 options、闭包或业务 key。
- 按系列所属值轴解释阈值；水平 Bar 的“值轴”仍是逻辑值轴，不误当屏幕 Y。
- 区分**原始值**与**绘制值/累计终点**：柱/条可选择，线/面积首批仅支持绘制值。调用方显式要求尚不支持的组合时给路径化诊断，不忽略。
- 区间采用 `[前一上限, 当前上限)`，阈值等于上限归后一段；有限上限严格递增，无上限只能在末段；未提供末段时剩余范围继承系列样式。
- 未配置保持旧外观；有效 zones 的优先级与现有 negativeColor/逐柱颜色一致。分区不改值域、原值、缺测、稳定身份、命中或图例身份。
- 第一切片只提供区间颜色；面积沿用系列既有填充规则。逐区渐变、多色标、X 类目索引分区及真实连续 X 分区另列后续，不能把这些差异静默吞掉。

**注意**：未纳入 schema 的能力不能声称“适配器已经拒绝”。对已建模却不被后端支持的组合提供诊断；未建模的旧字段须由未来 mapper 在丢失信息前报告。额外 JSON 键仍不能当作引擎配置通道。

## 5. 如果转向 G6，怎样拆分

推荐实施顺序如下，**不是说这三个任务都必须马上执行，也不是说反向轴是连续 X 的技术前置**。

### G6-A：反向值轴

- 保持 minimum < maximum 和数据原值；通过坐标变换改变显示方向，不颠倒数据数组，不以交换上下界代替。
- 覆盖主次轴独立反向、Line/Column/Bar/Combined；轴/网格、标注、颜色分区、标签、G1 堆叠/基线、选择/准线/命中须一致。
- 正反变换互逆、缩放锚点和可见范围须正确；主轴反向不能带反次轴。
- 通用 `isReversed` 已存在，原则上先补原生/OC/交互能力，再解除通过验收组合的适配器拒绝；不为“已有字段接通”无故升 schema 版本。

### G6-B：连续数值 X

- 首切片建议只开非堆叠直线 Line；范围限定后再评估曲线、面积、混合、柱宽和聚合，不一次放开所有形态。
- 用 X=`[0, 1, 10]` 验证位置间距为 1:9；视口、刻度、裁剪、缩放/平移和命中都使用真实坐标，业务身份仍用稳定 ID。
- 明确多系列不同 X 集合下的对齐/选择规则、缺测和单点/空域策略；保留输入严格递增校验，不静默排序或补点。
- 尚未接通的 mark/插值/堆叠/缺测政策逐组合拒绝。尤其类目 autoGap 的空位计数不能直接套到连续数值域。

### G6-C：连续时间 X

- 复用已经验证的连续坐标底座，使用模型既定 Unix 秒，不混入毫秒或把显示字符串当身份。
- 分别验证 08:00、08:05、09:00 的真实间距；时间格式、时区、跨日/DST、缺测时长和更新窗口政策。
- 时间聚合、稀疏多系列对齐、范围柱等另行立项；不能因支持时间标签就宣称完整时间序列能力已完成。
