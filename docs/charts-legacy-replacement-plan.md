## 0. 当前阶段：图表本体与通用模型分层

当前完成标准是：指定输入和配置能够在图表里正确画出目标形态，并能通过现有 Demo 直接检查。完整老模块替换仍是最终目标，但不再作为每一项绘制改进的前置条件。

新模型还要求：基础描述不依赖绘图库，身份/原始值/缺测含义稳定，适配器显式报告不支持的能力。首版已完成该基础链路，覆盖矩阵也已交付；不能据此推定全部旧字段或所有第三方引擎已经接通。

| 范围 | 本阶段处理方式 |
| --- | --- |
| 通用模型、能力诊断、后端转换 | 首版 `ChartSpecification` + HYMCharts 已交付；后续按覆盖矩阵和具体使用场景补充，其他后端仍待实现 |
| 折线/曲线/阶梯、面积/堆叠、柱/条、混合图，坐标轴、网格、分区、标线、数据标签 | 主线：补真实缺口和组合不完整处，复用已实现形态 |
| 图中的点/柱高亮、准线、命中、显隐、缩放 | 与展现直接相关，随受影响绘制能力验收；保留现有 Tooltip/图例功能 |
| 新绘制参数的 Swift/OC 入口、现有 Demo 面板 | 同批交付，证明配置确实生效；不先做一整套旧模型兼容层 |

图表内部的轴标签、标线文字、数据标签仍属于图表内容。图例/Tooltip 的现有功能不能退化，但业务统计内容不要求此时在 SDK 内重做。图中使用动态颜色后的图层更新属于本体正确性，不随外层主题卡片一起搁置。

## 1. 最终替换目标和范围（后续总验收）

完成替换必须同时满足：

1. 老项目实际使用的配置、数据输入、回调和页面状态都有明确映射；使用中的不支持字段有处理方案，不静默丢失。
2. Swift 和 Objective-C 业务页面能够导入独立图表产物，完成初次展示、刷新、显隐、选点与所需的外层 UI。
3. 同一份输入在旧版和新版的原始值、单位、正负方向、源索引及业务汇总一致。已识别的旧错误以明确的修正契约验收。
4. 布局、空态、深浅色、页面滚动、多图联动和全屏按使用页面验收；宽度与状态变化后可正常继续操作。
5. 代表页面完成同数据对照和逐页切换，有可用的回退路径；最终被替换模块不再引用 AA/Highcharts/JS 资源。

范围以当前封装和真实调用为准：Line / Spline / Area / AreaSpline / Column、混合与堆叠，以及配套组件。现有 Bar 等能力继续维护。Y 轴反向、对数轴、超过两根值轴、不等间隔 XY、HorizontalBezier、任意两线间填充、极坐标等，只有真实调用或明确新需求出现时才升级为本次阻塞任务。顶层 HMAAChartModel.chartType 是枚举，系列 HMAASeriesElement.chartType 和 xAxisType 是字符串；分别核查默认继承与允许值，未知值不能自动降级为折线。

## 2. 重新核对后的判断

### 已具备，继续复用并完善组合

- 混合图、系列样式、按轴/组/正负分链堆叠，原值/绘制值/百分比分离。
- autoGap、X/Y 连续 zones、曲线负值颜色；堆叠面积共享边界修复及明确的复杂过渡限制。
- 每系列数值格式、业务分组、小计、过滤、图标分栏、逐点样式、前值/偏移/置顶。
- 图片/自定义符号图例、显隐、统一测量；固定柱宽与间距、视口保留、折线采样和 Column 时间聚合。

这些能力不再重复建设。对齐阶段先关闭采样和聚合以核对原始索引与数值，验证后再按页面需要启用。

运行对照已收敛四条契约：普通/百分比的默认堆叠顺序需映射；百分比分母在正负样本中一致；缺测与手工分区应保持独立；旧“组当前值 + 行前值”和组独立格式不能等同于通用展示小计。已复现的仅数据刷新缓存、百分比轴 0…1、autoGap 覆盖颜色分区、程序选点未过滤隐藏提示行列入修正台账。

上述百分比与顺序数值结论仍限于 column 同组样本。新增面积运行确认：单组 2 条业务系列展开成 5 条、多组展开成 3 条；混合正负时的累计位置也不同，不能仅删除辅助系列并反转数组。混合 spline/area 的旧运行按具体 type 分链，HYM 按线族分链。R2 须分别处理业务身份、具体类型分组、累计策略和实际范围；groupID 继续只负责业务展示。

新侧对照已确认：具体类型加入兼容栈键后，混合样本 12 个代表点 raw/draw 对齐；面积业务 raw 对齐，但 −235/+103 的跨零累计位置仍不同。因此类型分区已有可行映射证据，面积累计效果仍需明确取舍，二者不再合成一个“堆叠待验证”任务。

新增修正项已具运行证据：拆分 helper 的 NSNull 异常及副本字段丢失、v2 原生中间组遗漏/右组标题错误、showNoData 修改 showLegend、跨业务组同栈面积被旧轴范围裁剪。面积正负累计差异本身不直接标为 bug：默认保留 HYM 正负独立链，真实页面如依赖旧抵消/绝对值填充，在 R0b 明确后单列兼容预设。

## 3. 分层与接入策略

依赖方向：业务页面 → 通用 `ChartSpecification` → 引擎适配器 → 目标绘图库。旧项目额外经过“旧输入 → 通用模型”的 mapper；该 mapper 尚未实现，当前后端仅 HYMCharts。

- **通用模型**：Foundation 值类型，定义数据、身份、轴、样式与校验/JSON 契约，不直接暴露 Highcharts options 或 HYMCharts renderer 参数。
- **引擎适配器**：检查目标库能力并转换配置；不支持时返回字段路径与原因，不静默改变坐标、缺测或堆叠含义。
- **通用 SDK**：绘制、数据/轴、数值格式、命中与选择、提示/图例、视口与测量。保留 Swift API，并为实际使用能力提供 OC 入口。
- **可选 UIKit 组件**：卡片、空态、布局组合、联动协调和全屏呈现；使用公开 SDK API。SwiftUI 为包装层，Demo 和 Debug 工具不进入库产品。
- **老项目适配层**：旧模型转通用模型、旧方法映射、能源 key 正负规则、默认主题、语言和图片注入、旧版布局预设。核心不引用 `Language`、命名资源、Masonry 或业务 key。

默认采用新的 SDK API 加薄适配层，集中减少页面修改；只保留已使用且值得兼容的旧签名。旧同名 facade 如必须保留，应在兼容目标内重建必要的数据契约，避免和旧实现重复定义类，也不能为了类型依赖重新引入整套 AAChartKit。

接入初期允许老项目在适配层选择旧/新实现用于对照和回退。这个选择属于老项目，SDK 自身从首个独立产物开始就不依赖 AA、WebView 或 JS。最终移除旧依赖前再核查其他业务模块是否仍使用它。

独立产物先满足 Swift/纯 OC 宿主导入、生成头和资源可用。采用 framework、SPM 还是老项目现有包管理方式，由真实工程约束决定；不同时维护多套未经验证的分发方式。当前仓库 iOS 15 配置不能直接当作老项目的最低版本。

R1 先用本仓库环境建立一种最小独立产物作导入验证，业务工程确认后再锁定正式最低版本和交付方式。宿主通过普通 `import` 或生成的 OC 头调用，不使用 `@testable`、私有 renderer 或把 SDK 源码再次编进宿主。保留 SwiftUI 公共包装，按文件/target 排除同目录下的 Demo、Debug 自检及参考代码；检查产物链接和资源依赖。纯 OC 宿主不依赖 App 自己的 bridging header 才能使用库。

运行对照宿主可同时使用两个不同类名的实现；同名兼容 facade 与旧同名类不能同时链接。页面开关在实例创建/重建时决定实现，切换有明确的失败回退与状态迁移策略，避免正在交互时混用两套回调。

此表是关键契约，不宣称覆盖全部公开字段。R0a 的逐字段/入口登记以旧 .h 文件为清单，至少记录层级、默认/继承、使用证据、Swift/OC 入口、适配归属、支持状态和验证用例。还应覆盖标题/轴字号字重、yAxisHidden/leftMargin、主次轴单位、标线标签样式、tooltipDisable/颜色/置顶、legend 背景/透明度、header margin、footer 图标、空态 nod*、放大按钮、delegate 垂直拖动及构造方式。尚未发现真实使用的字段可明确延期，不能从清单中消失。

索引联动默认只接受共享采样域的图表。定义稳定的采样域标识及原始索引/业务采样键；显示文字不作为唯一键，例如当前 3000 点 Demo 的 HH:mm 会重复。不同起点、间隔、长度或时区时提供显式映射与无匹配策略；格式化标签与时区/DST 展示分开。视口联动属于独立需求，旧 HMMTAAChartView 没有证明实现它。

### 状态转换和错误处理的最小约定

| 触发 | 验收要求 |
| --- | --- |
| 初次配置 / 显式重置 | 应用默认窗口或声明的初始范围；布局有效后才能宣告渲染完成 |
| 同采样域更新 | 默认保留用户视口并按新域收回；初始 defaultScope 不反复抢回用户窗口；当前 SDK 默认清除选择继续保持，恢复选择必须是显式策略 |
| 换日、换采样域或重排点 | 按域标识/采样键重置或显式重映射；不能把旧数组索引自动当成同一时间。范围恢复与系列显隐、选择恢复的应用顺序固定 |
| 图例、强制空态、全隐藏 | 隐藏后的选择失效可观测；全隐藏保留可恢复入口，强制空态撤销不丢模型/图例；全零仍为数据 |
| 结束/取消/离屏/销毁 | 提示、准线、统计表头同步切回约定状态；计时器/异步结果带版本检查；不重复通知、不由旧任务清掉新状态 |
| 程序选择 / 跨图同步 | 明确是否通知和事件来源；无效索引、缺测及无匹配键有结果；联动循环被阻断，清除也能传播 |
| 转换或配置失败 | 诊断含字段路径、原值、原因；无法支持的类型/轴/重复身份等不得静默降级，保持上一有效视图；可选外观降级须有明确记录 |

数据/模型可在约定线程准备，UIView、主题应用、provider 和回调在主线程使用；边界传递不可变快照。原有公开 API 默认行为保持，旧兼容策略通过适配预设显式启用。

## 6. 验收样本和证据

当前 G 阶段主要复用 F01/F02/F03 的绘制部分，并增加阈值着色、轴显隐/样式、标注和高亮案例。F04/F05 的旧提示契约、F07/F08/F09 的跨页面状态和外围组件在 R 阶段验收；空/缺测/全零、显隐与更新对绘制本体的影响仍需随 G 回归。

以下是持续补齐的验收集合。本次已重跑基线，补进共享面积/混合输入、持触提示和转换边界，范围见[对照结果](charts-legacy-demo-parity-results.md)。F01/F02/F03/F04/F06/F09/F10/F11 均仅完成其中一部分，不把一个通过用例等同整行完成。已有单元场景继续复用，不重复建立同图形 Demo 入口。

| 样本 | 最少覆盖 | 核心断言 |
| --- | --- | --- |
| F01 功率趋势 | 48 点确定性样本及 288/1440/2000/3000 点；直线/曲线/阶梯；首尾缺测、NaN、11/12/13 连续缺测、zones/负值/填充组合 | 源索引和 raw 不变；阈值与连断边界明确，曲线插值不成为新业务采样；平滑形状差异单独登记 |
| F02 正负堆叠 | 柱、单组/多组面积的普通/百分比、跨零、零分母、缺测、reverse/显隐；HYM 固定基准另作现有能力回归 | 分母、正负分链、draw/base/percentage 正确；面积拆分/虚拟系列不污染业务身份、原值和回调；复杂接缝有明确接受条件 |
| F03 混合双轴 | 两组柱 + 曲线/面积；同/不同具体类型共用 stackID；同/不同值轴与单位 | 具体类型的兼容分链、轴和柱槽正确；图例显隐、命中、组总量同步，跨单位不误求和 |
| F04 多组提示 | 旧两版原生与 JS 路径；≥3 组、组内 >10 项、短数组、独立表头/逐点名称、前值、整行隐藏/仅名称/仅数值 | 分别保留程序选点与持续触摸证据；不漏中间组、不串身份；当前索引/来源索引/组汇总明确；text/columns 不留多余冒号或漏值 |
| F05 数值与顺序 | 全部已用单位、金额工程进位、Locale、正负舍入/截断、负零、±999/1000、M/G 边界、特殊精度、reverse | 原值误差与格式化字符串分别断言；记录旧预舍入/浮点汇总差异；绘制/图例/提示顺序各自正确 |
| F06 空态与图例 | 空数组、全缺测、全零、全部隐藏、同一旧模型强制空态开/关、刷新后恢复 | 不修改调用方模型；全零有效、图例和选择按契约恢复；布局没有负高度 |
| F07 生命周期 | 手势/程序选点、抬手/取消、定时消失、连续更新、换日/换采样域、离屏/销毁、完成回调 | 事件来源/次数/版本可断言；无旧提示或计时器竞态；表头、选择、视口优先级一致 |
| F08 多图 | 同域/异域、不同长度/间隔、重复 HH:mm 标签、缺测/隐藏系列、无匹配键 | 以采样身份映射，不循环、不选错时间；清除可传播；不默认承诺视口同步 |
| F09 布局/主题/全屏 | 长中文/英文、窄容器、frame/Auto Layout、横竖屏、页面滚动、深浅色实时切换、全屏返回 | 测量与实际一致，断言解析后的颜色；窗口/显隐/选择按契约恢复，所属 windowScene/safe area 正确 |
| F10 集成/性能 | 普通 Swift/纯 OC 导入、Debug/Release、刷新/重排、3000 点交互、重复进入退出 | 不借助 @testable/私有 renderer；公开回调、依赖和资源正确；首个真实试点即满足记录过的性能预算 |

每个 fixture 保存 schemaVersion、输入内容散列、固定数据、映射配置和采样域身份；运行证据记录两侧源码版本、未提交改动的快照标识、设备/系统/构建方式、Locale/时区、用例和操作步骤。既有附件未记录的输入散列/源码快照标为未知，不事后伪造完整追溯信息。基线按版本保留，更新时记录原因。

同一用例分别保存“旧实际结果”和“新目标结果”：业务数值/回调契约、允许的视觉差异、已确认旧错误修正、待确认/不支持项分开判定。旧错误不能直接充当新版本的期望值。原始服务值、业务规范值、引擎绘制值、格式化文字分开对照；缺测位置和身份精确匹配，浮点值采用样本声明的容差，文字采用声明的单位和 Locale。

首个真实页面 R7 在扩大迁移前建立旧/新同设备、同输入、同 Release 配置的性能基线，记录预热方式、运行次数和至少以下指标，再确定该页预算：

| 指标 | 记录与验收 |
| --- | --- |
| 首次展示、连续刷新 | 使用一致的“有效布局/可交互”终点，记录中位数与高分位耗时，不能直接比较两套不同含义的 finishLoad |
| 长序列选择、缩放与滚动 | 记录交互响应和帧耗时/卡顿；先关闭采样/聚合校验语义，再分别记录启用后的性能与显示误差 |
| 重复进入/退出及全屏 | 记录峰值与回落后的内存、实例释放、遗留任务；旧 WKWebView 相关进程的内存口径注明，避免只比较 App 主进程 |

性能预算随代表设备和真实页面确定，不预设未经测量的提升比例。R8 复验全部迁移页；Debug 模拟器单次耗时不能作为真机性能保证。

## 7. 差异取舍与执行约定

继续保留单调曲线、原始数据语义、统一测量、显隐稳定身份、可选采样等现有长处。当前优先吸收可改善图表展现的绘制、坐标轴和样式能力；业务组、统计表头/空态、完整提示契约和页面集成后置，详见[三方能力对比](line-chart-parity-comparison.md)。

已复现问题按 D01–D04、D09–D12 修正；包括拆分 NSNull 异常/字段丢失、原生漏组/错标题、空态修改模型和面积范围裁剪。空值转零、短数组越界、次轴刻度误用、图例测量与渲染不一致等未补证项继续标为风险。D06 面积累计差异先按业务含义决定取舍，不能与明确 bug 混在一起。曲线形状、图例外观、Tooltip 排版允许有设计差异，须保证业务语义与可操作性；当前核心对照不宣称完整页面像素一致。

每个开发批次同时交付实现、必要的 Swift/OC 入口、现有 Demo 控件/命名预设、边界回归和映射记录。只为受影响路径增加测试。独立宿主验证属于集成测试，不增加同类型的重复产品 Demo 页。完成后更新本计划对应任务及[能力清单](charts-capability-status.md)。

当前待补信息：老项目路径、首批页面、实际 AA/Highcharts 版本、最低 iOS、构建/包管理方式、宏/资源依赖。缺少这些信息不阻止 G 图表本体实现和参考输入样本建设，但 R7/R8 必须基于真实工程完成。

历史说明：最初调整执行优先级的文档批次未修改绘制算法，也没有新增运行结果。此后 G1 常用组合及 2026-10-02 的 G2–G5 已按第 3 节完成，实际结果见对应证据；R1 与此前共享输入记录仍保留，不把后置的真实迁移事项删除或标成已完成。
