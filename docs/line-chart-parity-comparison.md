> 旧 Demo 的 11 个场景已运行；本轮完成逐场景对照、堆叠/缺测同输入验证及差异台账，见[运行对照结果](charts-legacy-demo-parity-results.md)。下方三方表继续用于能力与接口取舍，不代表完整业务页面已对等。

更新：2026-10-02。早期文档使用 KKChartKit 名称；本文以当前 HYMCharts 工作区实现为准。用途调整为：为老项目图表替换选择值得吸收的能力、辨认迁移阻塞项。执行顺序以[替换实施计划](charts-legacy-replacement-plan.md)为准，旧封装的行为证据见[迁移审计](charts-legacy-module-migration-audit.md)。

## 3. 三方值得借鉴的设计

| 方向 | AAChartKit / Highcharts | DGCharts | HYMCharts 的采用决定 |
| --- | --- | --- | --- |
| 配置组织 | AAChartKit 基于 Highcharts；上游有全局、类型、系列分层配置 | LineChartDataSet 集中管理连线、圆点、虚线、填充配置 | 保留主题 → 系列覆盖；为旧字段建立可核查的 OC 映射，不复制完整 JS options 树 |
| 选择和事件 | 上游有 point select/selected 等配置，旧封装另有程序选点入口 | 公开 highlight/clear 路径，支持控制是否触发 delegate | R4 采用显式选择/清除和事件来源，R6 防止联动循环 |
| 扩展与外层展示 | 旧项目自行增加原生分组提示、表头、图例、空态和全屏 | ChartViewBase 提供 Marker、无数据文本、选择/取消/拖动结束回调 | 用可选组件与注入资源承接，业务默认值留在项目适配层 |
| 曲线和点样式 | 与所使用的上游版本和配置相关，旧表的 Catmull-Rom 概括不作为兼容依据 | 当前源码有 linear/stepped/cubicBezier/horizontalBezier、cubicIntensity、circleColors、fillFormatter | 单调平滑继续作为工程曲线默认；其他形态按场景选用，fillFormatter 扩展口不能直接证明任意两线间填充 |
| 动画 | 上游系列/图表动画配置范围较广 | ChartViewBase 有 easing 参数；旧表的“DGCharts 无 easing”结论不正确 | 暂列按需增强；先满足旧页面展示、刷新和状态契约 |

来源（2026-09-30 查阅）：[AAChartKit 官方说明](https://github.com/AAChartModel/AAChartKit)、[Highcharts 系列配置](https://api.highcharts.com/highcharts/plotOptions.series.connectNulls)、[DGCharts LineChartDataSet](https://github.com/ChartsOrg/Charts/blob/master/Source/Charts/Data/Implementations/Standard/LineChartDataSet.swift)、[DGCharts ChartViewBase](https://github.com/ChartsOrg/Charts/blob/master/Source/Charts/Charts/ChartViewBase.swift)。旧封装的附加能力依据本仓库 HMAA/HM 源码，不能计为 AAChartKit 自带能力。

## 4. 必须明确的行为差异

- **曲线形态**：选择平滑算法时关注新增极值、工程数据解释和堆叠边界，不以 API 名称相同判定等价；取消“必然优于另外两库”的结论。
- **缺测与堆叠**：当前 Highcharts 文档说明，堆叠面积启用 connectNulls 时可将 null 解释为 0。HYMCharts 的迁移契约保留原始缺测与来源索引，必须用旧项目锁定版本的样本确认差异。[官方说明](https://api.highcharts.com/highcharts/plotOptions.series.connectNulls)
- **选择与联动**：有 crosshair、highlight 或 JS 选点函数，均不能单独证明原生提示、外部表头和全部图表状态已同步；这些要由端到端样本验证。
- **手势方向**：Bar 的纵向类目窗口与数值轴缩放要分别命名；双击重置继续保留现有默认，按页面约定决定是否需要其他策略。
- **前值与聚合**：前值是原始索引偏移，时间桶是区间统计，两者分开。回调中的当前命中与提示中的取值来源都有明确快照。
- **功能存在与可接入**：核心、SwiftUI、OC、项目适配层、独立产物和真实页面分别记录状态，不能用单层的“已实现”覆盖全部层。

## 5. 本次优先级结论

G1 常用过渡与 G2 柱/条阈值着色、G3 坐标轴、G4 图内标注、G5 主体选中反馈均已按既有 Demo 交付；配置与必要 Swift/OC 入口同步。当前继续回归并保留 G1 冲突缺测/退化百分比的明确回退；若扩大 G1 或进入 G6，先确定具体数据契约。统计表头、卡片/空态、业务提示汇总、全屏宿主后续通过外部 UIView 组合；正式旧输入转换也不作为绘制完善的前置。

详细任务、依赖、下一编码批次、字段契约和验收样本统一维护在[老项目替换实施计划](charts-legacy-replacement-plan.md)。本文件提供技术取舍，不再维护第二份相互冲突的执行队列。
