# 高密度时间序列与多系列柱状图方案

日期：2026-09-24。本文记录设计目标；其中 Column 等间隔时间聚合、区间命中及明细定位已完成第一版，接入与当前限制见 [使用指南](charts-time-grouping-guide.md)。同一数据版本的手势缓存和粒度切换缓冲也已接入；非堆叠直线/面积 Min/Max 已实现，详见 [折线降采样指南](charts-line-sampling-guide.md)；曲线/阶梯/堆叠降采样、跨 update 的差量失效与图层复用仍待实现。已确认业务需要每系列独立配置聚合方式。

## 规模与限制

通常按不重复计入次日 00:00 的一天计算：5 分钟间隔为 288 点，1 分钟间隔为 1440 点；未来按 2000–3000 点/系列设计。准确的时间边界还要考虑时区、夏令时和接口是否包含末端样本。

假设实际绘图区 320 pt，2000 个类目且每类目 3 根柱，在还没扣间距时，每根柱仅 `320 / 2000 / 3 ≈ 0.053 pt`。合并 layer 或换 GPU 可以改善帧耗时，无法让这么窄的柱子独立可读。必须分别解决渲染开销与展示密度。

实施前基线：Column 已有可见类目裁剪、同色复合 path；数据标签有限量规则，已有缩放和平移。没有按宽度进行的时间聚合或折线降采样。Line 仍构建较多点和 marker；柱状堆叠绘制在逐柱循环里调用 rawBaseValues，存在重复数组计算，后续应首先移出内层循环并缓存。

## 参考已有库的能力

- Highcharts **Stock** 根据轴宽度/数据密度进行 data grouping，支持配置时间粒度和聚合函数。[官方说明](https://www.highcharts.com/docs/stock/data-grouping)
- Chart.js 折线降采样提供 Min/Max 与 LTTB：前者保留峰值，后者用于简化趋势。[官方说明](https://www.chartjs.org/docs/latest/configuration/decimation.html)
- ChartsOrg/Charts 提供 setVisibleXRangeMaximum 和 moveViewToX，可限制一次看到的 X 范围并定位窗口。[源码](https://github.com/ChartsOrg/Charts/blob/master/Source/Charts/Charts/BarLineChartViewBase.swift)

下面是针对本 SDK 的设计建议，不代表上述库自动满足全部业务语义。

## 推荐交互：总览与明细

默认展示全天概况，根据绘图区宽度及可见系列数量选择时间粒度；提供“全天/最近几小时”快捷入口、点击聚合柱进入区间明细，以及原有捏合/拖动操作。这样首次看到就有可读概况，不用先手动缩放才能使用。

如果业务必须首次展示原始精确采样，则初始直接定位最近一段时间，只显示屏幕能容纳的类目数，横向拖动浏览；增加独立概览导航可帮助定位全天。无需建立超宽 UIView 或数千个子视图。

柱状图按**可见系列数和最小柱宽**决定组数，而不是写死超过 1000 点才优化：

```text
组宽预算 = 可见系列数 × 最小柱宽 + 组内间距总和 + 组间距
可读组数 ≈ floor(实际绘图区宽度 / 组宽预算)
```

例如设计每组约 16 pt，320 pt 绘图区可读约 20 组。全天模式选择业务允许的整齐时间档位，例如 2 小时一组得到 12 组；放大后逐级恢复到 1 小时、30 分钟、15 分钟、5 分钟，直至原始分辨率。16 pt 是演示预算，不是行业固定标准；实际按系列数、字体和产品需求调整。宽度应取图例/坐标轴扣除后的 plotFrame。

不要把“多系列并排”自动改成“堆叠”：异单位数据不能相加，同单位的不同对比对象也未必有相加意义。系列过多时可让用户选择少量系列，或用共享时间轴的小图分别展示。

## 同一个时间区间，不同系列聚合规则

先生成全图统一的时间边界，再逐系列应用 reducer。不能每个系列自己选不同的分桶边界。

| 指标语义 | 建议聚合 | 需要保留/说明 |
|---|---|---|
| 时间段内的增量电量 kWh、次数 | sum | 区间合计；有缺测时标记覆盖率 |
| 功率 kW、温度、电压 | average / timeWeightedAverage | 等间隔可简单平均；不等间隔需时间加权，明确样本覆盖时长 |
| 峰值告警 | max 或 min/max 范围 | 平均值会掩盖短时尖峰；范围需要额外视觉表达 |
| SOC、状态、时刻快照 | last 或业务 reducer | 末次有效值的实际时间；不是默认求和 |
| 累计电表读数 | 差值/业务 reducer | 边界插值、回零/复位必须显式处理，不能直接 sum |

未配置聚合方式的系列默认保持原始值或采用窗口模式，不根据图表类型擅自决定 sum。开放业务自定义 reducer，保留原始数据不覆盖。

缺失值不当成 0；桶内全缺失返回缺失，部分缺失返回有效计数/覆盖率。对时间加权明确长缺口是否允许插值，并设置最大有效间隔。不同单位继续按系列/值轴格式化，shared tooltip 分别注明单位和聚合方式。

对于正负堆叠，跨时间 sum 可能把正负抵消；必须按业务选择净值、正负分开聚合或不聚合，不能仅靠画法决定。百分比模式先聚合原始值，再用同一时间桶内可见系列重新求占比；一般不平均各原始点的百分比。固定基准必须说明是瞬时目标还是可按时长累加的区间目标。

## 折线与柱状采用不同的数据简化方式

折线优先按屏幕 X 范围保留 min/max，必要时保留 first/last，适合功率曲线保留尖峰。LTTB 可作为趋势展示的可选策略。降采样应按有效连续段处理，保留空值断点与真实时间坐标；不能平均后抹平短时异常，也不能按固定步长随便丢点。

柱状优先时间聚合，不使用 LTTB 抽几根柱代表区间总量。堆叠折线/面积需要共享采样位置或先计算累计边界，不能各系列独立抽点后直接堆叠。

## 数据与命中层设计（待实现）

```text
原始数据（稳定系列 ID、真实时间戳、单位）
  → 当前时间视口 / 绘图区宽度 / 可见系列数
  → 共用时间桶或采样计划
  → 每系列 reducer 与有效覆盖信息
  → 堆叠 / 百分比派生值
  → 布局、绘制和命中缓存
```

每个展示项保存 `sourceRange`/原始索引映射、时间区间、有效样本数、聚合函数、原始值范围和聚合值。点击聚合柱的 tooltip 显示“10:00–11:00，共 12 个有效采样，平均功率 …”，不能伪装成某个采样时刻的原始值。明细窗口可回查原始数据。

时间模型第一版可支持 startTime + interval 的等间隔序列；后续支持显式时间戳。当前等距类目索引不等于真实时间轴，缺样、不同采样率、同日 2000 点等情形不能仅靠数组下标推断。

渲染缓存应按数据版本、时间粒度、时间桶边界、reducer 配置失效；隐显、单位、百分比变化也要刷新对应派生值。平移时固定桶锚点，避免同一个时间桶随视口边界变动；切换粒度用阈值缓冲减少抖动。关闭高密度 marker/值标签，放大到稀疏后恢复。

## 建议落地顺序

1. 消除堆叠/归一化重复计算，补初始视口/快捷区间；用 288/1440/2000/3000 点 × 1/3/6 系列测量布局、缩放帧耗时和内存。
2. 接入时间与区间命中模型、每系列 reducer；先实现等间隔 Column 聚合，支持 sum/average/min/max/last/custom，测试缺测、正负值与边界。
3. 按组宽预算自动选择时间粒度，点击区间进入明细；绑定图例显隐与百分比语义。
4. 折线 Min/Max 降采样与 marker 密度策略，再考虑 LTTB、导航概览和更大规模服务端分辨率数据。

验收不只看 FPS：还要验证总量守恒、峰值保留、时间桶对齐、空值不断错、命中能够追溯原始值。当前尚无上述规模的真机性能实测，不承诺 3000 点的帧率。
